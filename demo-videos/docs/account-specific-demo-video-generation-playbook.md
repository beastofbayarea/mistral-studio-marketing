# Account-Specific Demo Video Generation Playbook

## Purpose

This playbook defines a repeatable method for creating short, account-specific field-enablement and concept-demo videos. It is intentionally company-, industry-, product-, workflow-, and role-neutral.

Use it for:

- Account-based sales and marketing videos
- Field-enablement conversation starters
- Product and workflow concept demonstrations
- Executive meeting openers
- Solution-engineering pre-reads
- Customer-success expansion narratives
- Partner and ecosystem demonstrations
- Event, social, and advertising derivatives

The recommended default is a 45–60 second horizontal master that makes one operational problem concrete, demonstrates one credible workflow, preserves human control, and ends with one measurable next step.

This is not a corporate film template. It is a compact decision narrative.

---

## 1. Generic variable system

Define these variables before writing a script or selecting footage.

| Variable | Meaning | Example categories |
|---|---|---|
| `{PROVIDER_COMPANY}` | Company presenting the solution | Software vendor, consultancy, platform provider |
| `{TARGET_COMPANY}` | Company or account receiving the video | Prospect, customer, partner, internal business unit |
| `{CREATOR_ROLE}` | Person using or presenting the video | PMM, account executive, solution engineer, CSM, consultant |
| `{VIEWER_ROLE}` | Primary intended viewer | Operations leader, CIO, product leader, analyst, frontline manager |
| `{INDUSTRY}` | Target operating context | Manufacturing, financial services, retail, healthcare, public sector |
| `{WORKFLOW}` | One workflow demonstrated | Incident investigation, underwriting, service triage, compliance review |
| `{TRIGGER}` | Event that starts the story | Anomaly, customer request, risk alert, missing document, delayed shipment |
| `{EVIDENCE}` | Inputs required to understand the event | Logs, documents, images, transactions, sensor readings, CRM records |
| `{FRICTION}` | Current operational difficulty | Fragmentation, delay, inconsistency, low confidence, manual coordination |
| `{SOLUTION}` | Product or service capability being demonstrated | Agent, workflow, search, orchestration, analytics, automation |
| `{HUMAN_APPROVER}` | Person accountable for the decision | Engineer, analyst, clinician, manager, compliance officer |
| `{DECISION}` | Action the workflow helps prepare | Diagnose, approve, escalate, resolve, route, recommend |
| `{OUTCOME}` | Business or operational result | Faster response, stronger evidence, reduced rework, clearer accountability |
| `{CTA}` | Single requested next step | Define a pilot, map a workflow, run a workshop, review architecture |
| `{DISCLOSURE_STATUS}` | Relationship of the video to the companies shown | Official asset, approved concept, internal draft, personal concept |

Do not continue until every variable has a concrete answer. Generic claims usually come from undefined variables.

## 2. Decide what the video must accomplish

Choose one primary job.

1. **Earn attention:** make a relevant problem feel immediate.
2. **Make a workflow tangible:** show how a capability operates in context.
3. **Enable a conversation:** help a field team introduce a credible use case.
4. **Create internal alignment:** give stakeholders a shared picture of a proposed workflow.
5. **Convert interest:** move the viewer toward a workshop, pilot, assessment, or review.

A short video should not attempt to explain an entire platform, company strategy, architecture, and implementation plan. It should make one decision path memorable.

### Recommended objective statement

> After watching, `{VIEWER_ROLE}` should understand how `{SOLUTION}` could help `{TARGET_COMPANY}` move from `{TRIGGER}` to `{DECISION}` with stronger `{EVIDENCE}` and clear `{HUMAN_APPROVER}` control—and agree to `{CTA}`.

## 3. Select the right workflow

Score candidate workflows from 1–5 against the following criteria.

| Criterion | Question |
|---|---|
| Relevance | Is this visibly connected to the target company and viewer role? |
| Urgency | Does delay, inconsistency, or uncertainty create meaningful consequences? |
| Visual potential | Can the trigger, evidence, reasoning, review, and result be shown? |
| Product proof | Can the solution be demonstrated rather than merely described? |
| Human control | Is there a clear accountable decision-maker? |
| Measurability | Can a pilot have observable success measures? |
| Credibility | Can the narrative avoid unsupported deployment or outcome claims? |

Prefer the highest-scoring workflow. If two workflows are equally strong, choose the one with the clearer visual contrast between the current problem and the proposed decision path.

### Strong workflow shapes

- Detect → investigate → explain → approve → act
- Receive → classify → validate → route → resolve
- Gather → compare → challenge → decide → document
- Monitor → identify → diagnose → review → intervene
- Request → retrieve → synthesize → approve → respond
- Plan → simulate → evaluate → authorize → execute

## 4. Adapt the story to the creator and viewer roles

The workflow may remain the same while proof, language, and CTA change.

| `{CREATOR_ROLE}` | Emphasize | Avoid | Recommended CTA |
|---|---|---|---|
| Product marketer | Use-case relevance, differentiation, outcome narrative | Deep implementation detail | Define the pilot and success measures |
| Account executive | Account priorities, urgency, business value | Feature inventory | Select one high-value workflow |
| Solution engineer | Inputs, controls, integration points, traceability | Unsupported business claims | Map architecture and data access |
| Customer-success manager | Adoption, expansion, governance, repeatability | Net-new transformation language | Prioritize an expansion workflow |
| Consultant | Operating model, decision process, measurable change | Product-only framing | Run a discovery workshop |
| Product manager | User problem, workflow friction, decision quality | Sales language | Validate the workflow with users |
| Executive sponsor | Strategic consequence, speed, control, measurable outcome | Interface detail | Sponsor a bounded pilot |

| `{VIEWER_ROLE}` | Show more of | Show less of |
|---|---|---|
| Executive | Stakes, control, outcomes, next step | Dense interface footage |
| Technical leader | Architecture, data boundaries, observability, evaluation | Vague transformation language |
| Domain expert | Evidence quality, exceptions, review, reasoning | Generic industry montage |
| Frontline operator | Usability, handoffs, speed, clarity | Abstract platform diagrams |
| Risk or compliance leader | Approval, provenance, audit trail, uncertainty handling | Autonomous-action imagery |
| Procurement or finance | Scope, measurability, implementation boundary | Unbounded future-state promises |

## 5. Recommended duration and story architecture

### Default 45–60 second master

| Time | Beat | Narrative purpose | Visual purpose |
|---:|---|---|---|
| 00:00–00:03 | Trigger | Create immediate tension | Three fast, literal impact shots |
| 00:03–00:08 | Stakes | Explain why the event matters now | Consequence, motion, or operational context |
| 00:08–00:14 | Complexity | Show fragmented inputs or uncertainty | Diverse evidence sources |
| 00:14–00:21 | Control layer | Introduce the solution in context | Product proof point, not a product tour |
| 00:21–00:29 | Reasoning | Compare, identify conflicts, or request evidence | Literal comparison and uncertainty states |
| 00:29–00:37 | Human decision | Keep the accountable expert in control | Review, challenge, approval, or escalation |
| 00:37–00:44 | Outcome | State the operational improvement | Physical or digital action and traceability |
| 00:44–00:52 | CTA | Convert interest into one next step | Dedicated action-oriented end card |

Timing may move by a few seconds, but the sequence should remain intact.

### 30-second version

- 0–3 seconds: trigger
- 3–8 seconds: stakes and fragmented evidence
- 8–16 seconds: solution and reasoning
- 16–23 seconds: human approval and result
- 23–30 seconds: CTA

Do not accelerate a 60-second script to fit 30 seconds. Rewrite it.

### 60–90 second version

Use the additional time for one of these—not all of them:

- One deeper product interaction
- One exception or uncertainty branch
- One architecture or governance proof point
- One quantified pilot success measure

## 6. Script-writing framework

Write the narration before assembling the final timeline. Visual research may inform the script, but the final narration must provide the story spine.

### Generic 50-second narration template

> `{TRIGGER}` detected.
>
> The evidence is scattered—and every second matters.
>
> The signal could begin anywhere: `{EVIDENCE_SOURCE_1}`, `{EVIDENCE_SOURCE_2}`, `{EVIDENCE_SOURCE_3}`, or `{EVIDENCE_SOURCE_4}`.
>
> `{SOLUTION}` brings every source into one controlled, traceable workflow.
>
> It compares what happened before, surfaces conflicting signals, and builds a concise decision brief.
>
> Not enough confidence? It asks for more evidence instead of guessing.
>
> `{HUMAN_APPROVER}` reviews the reasoning, challenges it, and adds operational judgment.
>
> Only an approved action moves forward, with every decision traceable.
>
> The result: `{OUTCOME_1}`, `{OUTCOME_2}`, and a clear path to `{DECISION}`.
>
> Let’s `{CTA}`.

### Writing rules

- Use one idea per sentence.
- Prefer verbs over abstract nouns.
- Name concrete evidence sources.
- Describe what the workflow does, not what the technology “is.”
- Keep unsupported metrics out of the narration.
- Avoid “revolutionary,” “seamless,” “transformative,” and similar filler.
- State uncertainty behavior explicitly when it matters.
- State human approval explicitly when the workflow affects consequential actions.
- End with one CTA, not a list of possible next steps.
- Read the script aloud before synthesizing or recording it.

### Claim discipline

Distinguish among:

- **Observed fact:** visible in approved source material or product behavior
- **Proposed capability:** could support, can be configured to, conceptually enables
- **Demonstrated behavior:** shown in the concept or prototype
- **Deployed behavior:** verified as running in the target environment
- **Measured outcome:** supported by approved evidence and methodology

Never describe a proposed workflow as deployed. Never convert a concept visual into a customer claim.

## 7. Narration performance

### Voice selection

Choose a voice that is:

- Clear at mobile playback volume
- Warm and consultative rather than announcer-like
- Capable of urgency without sounding alarmist
- Comfortable with technical and company-specific terms
- Consistent across individually generated cues

When pronunciation matters, test company names, product names, acronyms, and domain terms separately.

### Generate or record sentence by sentence

Separate cues allow precise control of:

- Start time
- Pace
- Pitch
- Emphasis
- Volume
- Pause length
- Pronunciation
- Retakes without regenerating the full performance

Do not synthesize one long paragraph and cut it mechanically.

### Performance arc

| Beat | Delivery direction |
|---|---|
| Trigger | Short, forceful, low or neutral pitch |
| Stakes | Deliberate, controlled urgency |
| Complexity | Faster enumeration with clear consonants |
| Solution | Confident and grounded |
| Reasoning | Curious, precise, slightly varied pitch |
| Uncertainty | Inquisitive; allow the question to breathe |
| Human control | Authoritative and reassuring |
| Outcome | Brighter, faster, more optimistic |
| CTA | Warm, energetic, direct |

### Prevent robotic narration

- Vary pace and pitch by sentence rather than applying one global setting.
- Use punctuation to shape phrasing, but do not create excessive pauses.
- Keep enough contrast between low-stakes and high-energy lines.
- Avoid making every cue faster, louder, and higher; uniform intensity sounds artificial.
- Use light presence enhancement around the consonant range.
- Preserve dynamics with moderate compression.
- Keep the voice centered and clearly above the score.

### Timing rules

- No cue may overlap the next cue unless the overlap is intentional and intelligible.
- Narration should begin within the first 100 milliseconds for an ad-like cut.
- Allow 100–300 milliseconds after important phrases when the visual needs to land.
- Verify that every narrated clause has a matching visual during the same interval.
- Do not repeat a sentence or clause unless repetition is a deliberate rhetorical device.

## 8. Visual sourcing strategy

Build a footage library before editing. Organize sources by visual function, not only by provider.

### Required visual families

1. **Trigger:** anomaly, alert, failure, request, exception, or time pressure
2. **Operating context:** the environment in which the workflow matters
3. **Evidence sources:** documents, interfaces, physical systems, data, records, images
4. **Product proof:** the actual solution performing a relevant action
5. **Reasoning:** comparison, retrieval, conflict detection, confidence, synthesis
6. **Human control:** review, challenge, approval, escalation, judgment
7. **Outcome:** routed action, completed task, resolved state, traceable record
8. **CTA:** a clean visual or branded end card with one next step

### Sources to consider

- Approved company footage
- Product screen recordings
- Customer or partner footage with permission
- Industry-process footage
- Public-domain footage
- Licensed stock footage
- Original screen mockups
- Motion graphics and diagrams
- Macro photography
- Abstract physical metaphors
- Maps, control rooms, logistics flows, laboratories, field operations, or other domain environments

Think beyond literal product footage. A workflow involving evidence and decisions may benefit from forensic imagery, air-traffic coordination, mission control, quality inspection, scientific instrumentation, or other visually analogous systems—provided the analogy is clear and not misleading.

### Footage inventory fields

Record these attributes for every source:

| Field | Purpose |
|---|---|
| Descriptive filename | Makes reuse and search practical |
| Source URL or owner | Preserves provenance |
| Rights status | Approved, licensed, public domain, pending, unknown |
| Duration and resolution | Identifies technical limitations |
| Useful time ranges | Avoids rescanning entire files |
| Visible brands | Flags crop or replacement needs |
| Talking heads | Flags prohibited ranges |
| Embedded subtitles | Flags unrelated or unusable ranges |
| Primary visual family | Trigger, product proof, outcome, and so on |
| Reuse count | Prevents accidental repetition |

## 9. Visual selection rules

### Match each clause literally

Create a narration-to-visual map before the final cut.

| Narration clause | Required visual meaning | Selected source | Source range | Edit range | Risk |
|---|---|---|---:|---:|---|
| `{CLAUSE}` | `{WHAT_VIEWER_MUST_SEE}` | `{FILE}` | `{IN–OUT}` | `{IN–OUT}` | Branding, subtitles, mismatch, repetition |

A beautiful visual is still wrong if it communicates a different idea from the narration.

Examples:

- “Compares prior incidents” should show comparison, history, versions, or retrieval—not a generic machine.
- “Surfaces conflicting signals” should show two differing representations or a visible mismatch.
- “Requests more evidence” should show an evidence request, missing input, or confidence state.
- “Engineer approves” should show review and approval—not autonomous execution.
- “Clear path to action” should show routing, execution, or a resolved decision state.

### Visual diversity targets

For a 45–60 second video:

- Use 18–26 shots.
- Keep most shots between 1.5 and 3 seconds.
- Use more rapid shots only during the opening or a deliberate montage.
- Avoid using the same exact shot more than once.
- Avoid using near-identical ranges from the same source unless the repetition has narrative meaning.
- Use at least four distinct visual families.
- Use product footage as proof points, not as half of the entire video.
- A useful starting range is 20–35% product footage and 65–80% contextual, evidence, human-control, and outcome footage. Adjust for the audience.

### Talking heads

If talking heads are not explicitly approved, exclude them without exception.

Human presence can still appear through:

- Hands operating equipment
- Over-the-shoulder review
- Operators walking through an environment
- Team collaboration without direct-to-camera speech
- Expert interaction with the actual workflow

Create contact sheets for full source videos. A talking-head segment hidden near the end is still a talking-head segment.

### Embedded subtitles and unrelated text

- Exclude ranges with unrelated subtitles whenever possible.
- Do not cover a large subtitle area with another large overlay.
- Crop only when the important subject remains intact.
- Avoid product footage whose source captions contradict the narration.
- Review the bottom, top, and corner safe areas separately; watermarks often appear intermittently.

### Third-party branding

- Keep only brands that are authorized and relevant to the story.
- Replace a shot if the brand occupies a large or central area.
- Crop edge watermarks only when composition and resolution remain strong.
- Do not blur a large logo if the blur becomes more distracting than the logo.
- Review every frame in a selected range; branding may enter after the first frame.

## 10. Product-footage rules

Product footage must prove the narration rather than interrupt it.

### Strong product proof points

- Connecting a source
- Configuring a workflow
- Comparing versions
- Retrieving relevant evidence
- Displaying confidence or uncertainty
- Requesting clarification
- Producing a concise brief
- Showing an approval gate
- Displaying traceability or execution history

### Weak product footage

- Long cursor movement
- Empty loading states
- Tiny unreadable interface views
- Generic dashboards unrelated to the narration
- Repeated shots of the same page
- Feature tours that stop the story
- Screen recordings with unrelated notifications, tabs, or subtitles

### Presentation

- Crop to the important interaction.
- Enlarge the meaningful UI region.
- Preserve enough surrounding interface to maintain credibility.
- Use a consistent frame, border, or background treatment.
- Keep product shots concise—usually 1.5–3 seconds.
- Do not stack multiple text overlays over dense interface text.

## 11. Text overlays

Text overlays are emphasis, not captions for every spoken word.

### Content rules

- One thought per overlay
- Prefer 2–6 words
- Use no more than two lines
- Do not repeat the same phrase in adjacent shots
- Do not duplicate a phrase already visible in the source footage
- Keep overlays synchronized with the exact narration clause
- Remove filler labels that do not change the viewer’s understanding

### Size and layout

For 1920 × 1080 delivery:

- Primary impact text: approximately 72–120 pixels
- Supporting step labels: approximately 42–64 pixels
- Disclosures and source notes: approximately 24–34 pixels
- Keep the text container only as large as required by the copy.
- Minimize empty space inside overlay boxes.
- Preserve adequate padding around the text.
- Keep essential text within title-safe margins.

The text should be large; the box around it should be small.

### Placement

- Use a consistent anchor unless the underlying subject requires a change.
- Keep important imagery unobstructed.
- Avoid the lowest area when platform controls may cover it.
- Avoid the upper-right area when account or platform branding occupies it.
- Vertically center end-card content instead of letting it drift toward the top.

## 12. Design system and motion

Create a small, reusable visual system derived from the presenting company’s approved brand guidance.

Recommended elements:

- One primary dark or neutral background
- One accent color for detection, focus, or action
- One warning color for uncertainty
- One success color for approval
- One display typeface and one body typeface
- A consistent grid or technical-line treatment
- A repeatable product frame
- A consistent logo safe area
- One transition language

### Restrained motion graphics

Restrained motion graphics are subtle animated elements that clarify hierarchy without competing with the footage. Examples include:

- A short accent rail entering with a label
- A thin outline highlighting a discrepancy
- A slow grid or data-line drift
- A controlled push-in on a static frame
- A brief pulse on an approval state
- A small progress marker tied to the story beat

Avoid excessive particles, spinning shapes, random glitch effects, or motion that implies system behavior not actually demonstrated.

### Transition rules

- Prefer clean editorial cuts.
- Use match cuts when shape, movement, or color can connect two shots.
- Use a short audio bridge across visually different scenes.
- Use a brief dip, blur, or motion transition only when a hard cut is genuinely jarring.
- Do not use a different transition style for every cut.
- Check the frame before and after every major transition; subject position and brightness should not jump without purpose.

## 13. Background score and sound design

A narration-only export often feels unfinished. Use a score that supports the decision arc.

### Score structure

| Story beat | Musical behavior |
|---|---|
| Trigger | Impact, pulse, tension, immediate energy |
| Complexity | Restrained rhythm and unresolved harmony |
| Solution | Wider harmonic space and clearer forward motion |
| Reasoning | Subtle pulse or motif; avoid distraction |
| Human decision | Controlled emphasis and temporary space |
| Outcome | Brighter harmony or stronger rhythmic confidence |
| CTA | Resolve, lift, and finish cleanly |

### Mix rules

- Keep the voice clearly dominant.
- Use sidechain ducking or manual automation beneath narration.
- Reduce dense high-frequency music under technical language.
- Keep impacts short and synchronized with visual events.
- Maintain an audible bed or intentional ambience at every frame.
- Do not leave unexplained silent gaps.
- Fade or resolve the score at the exact end of the video.
- Avoid copyrighted commercial music unless explicit licensing covers the intended distribution.

### Sound-effect rules

Use effects to mark meaningful state changes:

- Detection
- Evidence request
- Approval
- Execution
- CTA arrival

Do not add a sound effect to every cut.

## 14. End card and CTA

The end card must tell the viewer what to do next.

### CTA formula

> `{ACTION_VERB}` one `{HIGH_VALUE_WORKFLOW}` into a `{MEASURABLE_NEXT_STEP}`.

Examples:

- Define one high-value workflow and launch a measurable pilot.
- Map the data, controls, and success measures for one decision process.
- Select one service journey for a focused working session.
- Prioritize one expansion workflow and define adoption milestones.
- Review one architecture path with the technical stakeholders.

### End-card content hierarchy

1. Small relationship or context label
2. One outcome-oriented headline
3. One line describing the working session or next step
4. One clear button-style CTA
5. Optional disclosure if required

### End-card rules

- Hold for at least 3.5 seconds.
- Vertically center the complete content group.
- Ensure any accompanying image is fully visible from its first frame.
- Do not animate the image from a visibly cropped or incomplete state.
- Keep the CTA readable without pausing.
- Use only one action.

## 15. Disclosure, brand status, and metadata

Before distribution, classify the video.

| Status | Required treatment |
|---|---|
| Official company asset | Approved branding, claims, legal review, and publishing channel |
| Approved concept | State that the workflow is representative if it is not deployed |
| Internal field-enablement draft | Mark as internal or draft in the file and distribution context |
| Personal or unofficial concept | State clearly in the title or description that it is not an official company video |

The disclosure does not have to dominate the thumbnail unless policy requires it. The title and first lines of the description are usually the clearest place for public disclosure.

### Generic public description disclosure

> This is a personal field-enablement concept. It is not an official `{PROVIDER_COMPANY}` or `{TARGET_COMPANY}` company video, advertisement, customer case study, product announcement, or representation of a deployed workflow.

### Metadata rules

- Strip inherited title, artist, description, and comment metadata from source footage.
- Write deliberate title and artist metadata to the delivery master.
- Do not allow a third-party source owner to appear as the artist of the final export.
- Use a descriptive filename rather than an internal working title.

## 16. YouTube title, description, and thumbnail

### Title formula

> `{OUTCOME_OR_TRANSFORMATION}: A {WORKFLOW_TYPE} Concept for {TARGET_COMPANY} | {PROVIDER_COMPANY}`

If disclosure is required in the title:

> `Unofficial Demo Concept: {OUTCOME_OR_TRANSFORMATION} | {TARGET_COMPANY} × {PROVIDER_COMPANY}`

### Description structure

1. Disclosure, when required
2. One-sentence problem and promise
3. What the workflow demonstrates
4. Synthetic or representative-data statement
5. Relevant product or industry link
6. Three or four focused hashtags

### Thumbnail rules

- Use 1280 × 720 pixels.
- Use one focal image and one primary headline.
- Keep the headline to roughly 2–5 words.
- Use high contrast and large type.
- Ensure readability at 10–15% of full size.
- Use approved company logos without redrawing or distorting them.
- Keep logos secondary to the story headline.
- Avoid screenshots with tiny interface details.
- Avoid talking heads unless the video is intentionally personality-led.
- Do not add a disclosure badge unless required or strategically helpful; keep the disclosure in the title and description when appropriate.

## 17. Technical delivery specifications

### Horizontal master

- Canvas: 1920 × 1080
- Aspect ratio: 16:9
- Frame rate: 30 fps unless source or channel requirements differ
- Video codec: H.264 High Profile
- Pixel format: yuv420p
- Audio: AAC stereo, 48 kHz, approximately 192 kbps
- Web playback: fast-start metadata enabled
- Recommended runtime: 45–60 seconds

### Social derivatives

Do not mechanically crop the horizontal master and assume the result is native to another platform.

For each derivative:

- Reframe each shot for the new canvas.
- Rebuild overlays at the new resolution.
- Respect platform interface safe areas.
- Reconsider shot duration and text density.
- Rebuild the end card.
- Preserve interface legibility.
- Treat a weak derivative as optional; the horizontal master remains canonical until a channel-specific edit is approved.

### Naming convention

```text
{target-company}-{workflow}-{format}-{duration}-{resolution}-v{number}.{extension}
```

Example:

```text
exampleco-incident-investigation-field-demo-52s-1080p-v3.mp4
```

## 19. Reproducible build system

Use the smallest practical toolchain.

Recommended components:

- FFmpeg for deterministic video, audio, crop, scale, subtitle, and encoding operations
- A small script for repeatable input mapping and rendering
- JSON or YAML for narration text, cue timing, voice, pace, pitch, and gain
- ASS subtitles for time-based overlays and typography
- Version-controlled scripts, overlays, narration configuration, and documentation
- Ignored generated video and audio caches when repository size matters

### Build requirements

- Every source input must use an explicit source-in time and duration.
- Every output shot must have a stable label.
- Narration cue timing must live in data, not only inside an editor timeline.
- The end card must be reproducible.
- Output metadata must be written deliberately.
- Rebuilding must not require manually repeating undocumented editor steps.

## 20. Production workflow

### Phase 1: Brief

1. Define the viewer, workflow, decision, outcome, and CTA.
2. Classify disclosure status.
3. Write the objective statement.
4. Select the distribution channel and runtime.

### Phase 2: Research and ingest

1. Gather approved product, account, industry, and contextual footage.
2. Rename files descriptively.
3. Record provenance and rights status.
4. Generate contact sheets.
5. Flag talking heads, brands, subtitles, low resolution, and unusable ranges.

### Phase 3: Narrative

1. Write the 45–60 second script.
2. Remove unsupported claims.
3. Divide it into individually directed cues.
4. Create the narration-to-visual map.

### Phase 4: Rough cut

1. Build the opening first.
2. Select one literal visual per narration clause.
3. Limit product footage to concise proof points.
4. Establish visual diversity before adding overlays.
5. Add the action-oriented end card.

### Phase 5: Audio

1. Generate or record each cue.
2. Correct pronunciation and overlaps.
3. Add an evolving score.
4. Duck the score beneath narration.
5. Add only meaningful state-change effects.

### Phase 6: Graphics and finishing

1. Apply the approved design system.
2. Add short, large overlays.
3. Remove duplicated copy.
4. Correct awkward crops and incomplete image entrances.
5. Smooth jarring transitions.

### Phase 7: Delivery

1. Write deliberate metadata.
2. Export the horizontal master.
3. Prepare the title, description, and thumbnail.
4. Create channel derivatives only when needed.
5. Preserve the build definition and edit map.

## 21. Quality-control gates

### Narrative gate

- [ ] The video covers one workflow.
- [ ] The opening creates tension within three seconds.
- [ ] Every sentence advances the story.
- [ ] Human responsibility is explicit.
- [ ] The CTA requests one next step.

### Visual gate

- [ ] Every narration clause has a matching visual.
- [ ] No talking heads appear unless explicitly approved.
- [ ] No unrelated embedded subtitles appear.
- [ ] No unauthorized or distracting brands appear.
- [ ] No exact shot is reused accidentally.
- [ ] Near-duplicate source ranges are minimized.
- [ ] Product footage is concise and legible.
- [ ] The end-card image is fully visible from its first frame.

### Text gate

- [ ] Overlays contain one thought and no more than two lines.
- [ ] Primary text is readable on a laptop and mobile preview.
- [ ] Overlay boxes contain minimal empty space.
- [ ] No phrase is accidentally duplicated.
- [ ] End-card content is vertically centered.

### Narration gate

- [ ] The first cue begins immediately.
- [ ] Delivery varies by story beat.
- [ ] Technical terms and names are pronounced correctly.
- [ ] No cue overlaps another unintentionally.
- [ ] No narration phrase is repeated accidentally.
- [ ] Voice modulation sounds energetic but intelligible.

### Audio gate

- [ ] A score or intentional ambience supports every frame.
- [ ] The voice remains clearly dominant.
- [ ] Music changes with the story arc.
- [ ] Sound effects mark only meaningful transitions.
- [ ] No unexpected silence appears.
- [ ] The final frame has a clean audio resolution.

### Brand and disclosure gate

- [ ] Logo assets are approved and undistorted.
- [ ] The relationship between the companies is represented accurately.
- [ ] Concept, deployment, and outcome claims are clearly distinguished.
- [ ] Public disclosure matches `{DISCLOSURE_STATUS}`.
- [ ] File metadata does not inherit third-party source information.

### Technical gate

- [ ] Resolution, aspect ratio, frame rate, codec, and audio format match delivery requirements.
- [ ] The runtime is within the channel limit.
- [ ] The file begins playback quickly.
- [ ] The delivery filename is descriptive and versioned.

## 22. Common failure modes and fixes

| Failure | Likely cause | Fix |
|---|---|---|
| Boring opening | Context before tension | Start with the trigger and three rapid literal shots |
| Robotic voice | One global voice setting or one long synthesis | Generate cues separately and direct each beat |
| Monotonous delivery | Uniform pace, pitch, and volume | Build a performance arc with deliberate contrast |
| Narration and visuals disagree | Clips chosen for aesthetics rather than meaning | Map every clause to a literal visual requirement |
| Long gaps without narration | Cue timing inherited from a longer cut | Retighten the timeline or let purposeful score/ambience carry the frame |
| No audio at parts of the video | Music bed or audio track ends early | Extend and trim the final mix to the exact video duration |
| Talking head appears late | Only opening contact sheets were reviewed | Inspect the full selected range frame by frame |
| Unrelated subtitles remain | Source range was selected without text review | Replace the range or use a clean crop |
| Third-party logos remain | Branding enters after the first frame | Review the entire range and replace when cropping is insufficient |
| Product footage dominates | Product tour substituted for a workflow story | Reduce product footage to specific proof points |
| Same visual appears twice | Reuse count was not tracked | Add source ranges and reuse counts to the edit map |
| Duplicate overlay phrase | Copy was authored independently of the timeline | Maintain one overlay source of truth |
| Duplicate narration phrase | Cue files were reused or placed twice | Tie one audio file to one cue ID |
| Jarring transition | Large changes in brightness, scale, or subject position | Use a match cut, audio bridge, or short controlled transition |
| Overlay box feels too large | Container sized independently of the copy | Crop the container to text plus consistent padding |
| Text remains unreadable | Landscape design judged only at full-screen size | Review at thumbnail and mobile preview sizes |
| End-card image begins cropped | Image animation starts outside its intended frame | Start from a complete composition, then animate subtly |
| CTA is passive | End card summarizes instead of asking | Use an action verb and measurable next step |
| Export credits a source owner | Metadata inherited from the first input | Strip source metadata and write final metadata explicitly |
| Social derivative looks weak | Horizontal master was mechanically cropped | Re-edit for the target canvas or skip the derivative |

## 25. Definition of done

A video is complete when:

1. One target viewer and one workflow are unmistakable.
2. The opening earns attention immediately.
3. Every spoken clause has a literal, relevant visual.
4. No prohibited talking heads, subtitles, or brands remain.
5. Product footage proves the workflow without dominating it.
6. Narration is energetic, varied, clear, and non-repetitive.
7. Music supports every frame and ducks beneath the voice.
8. Text is concise, large, and minimally boxed.
9. Human review and approval are explicit where required.
10. The end card requests one measurable next step.
11. Disclosure accurately reflects the asset’s official status.
12. The master, thumbnail, metadata, build definition, and edit map are all documented and reproducible.

If any of these conditions is false, the video is still a draft.
